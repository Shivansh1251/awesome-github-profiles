# Launch and discoverability checklist

## First publish

Create an **empty, public** repository named **Awesome-github-profiles** under [Shivansh1251](https://github.com/Shivansh1251). Do not initialize it with a README or license, because this local repository already includes both. Then connect and push this checkout:

~~~sh
git remote add origin https://github.com/Shivansh1251/Awesome-github-profiles.git
git push -u origin main
~~~

The README is written to make the project easy to understand and to use relevant phrases naturally. Google decides whether and where to show a result; no README can guarantee a first-page ranking. Finish these repository-level steps after the public GitHub repository exists.

## GitHub repository settings

- [ ] Create a **public** repository named awesome-github-profiles under the account that will maintain it.
- [ ] Set the repository description to: A curated directory of inspiring GitHub profiles and profile README examples. Discover ideas and submit your own.
- [ ] Add relevant repository topics: awesome-list, github-profiles, github-profile-readme, profile-readme, developer-portfolio, open-source, community, and developer-resources.
- [ ] Set the homepage URL if the project gets a companion website.
- [ ] Add a useful social preview image after the project has a visual identity.
- [ ] Confirm that Issues and pull requests are enabled. Enable Discussions if you want profile ideas and questions outside pull requests.
- [ ] Keep the README, contribution guide, license, and profile entries current.

## Google Search

1. Make sure the GitHub repository is public and contains useful, original profile entries.
2. Share the project where developer profile examples are relevant, such as your portfolio, a blog post, or a community resource list. Avoid spammy link drops.
3. Search for the exact repository name and URL occasionally to see whether Google has indexed it. Indexing and ranking take time and are not guaranteed.
4. If you publish a companion website on a domain you control, verify that site in [Google Search Console](https://search.google.com/search-console), submit its sitemap, and monitor indexing and search queries.

A GitHub repository page does not give you full control over its page title, meta description, or sitemap. A small GitHub Pages site can provide those controls and a clearer landing page, but it is an optional next step; it does not guarantee that Google will rank the site or repository above similar projects.

## Keep the directory useful

- Add original profiles with short, specific reasons to visit them.
- Keep the selection criteria visible and apply them consistently.
- Accept thoughtful submissions from developers at every experience level.
- Review stale profile links and honor correction or removal requests.
- Ask contributors and visitors what profile examples they want to discover next.
